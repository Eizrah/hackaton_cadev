1. Le langage, le moteur et la base

SQL signifie Structured Query Language, langage de requêtes structuré. Il permet de décrire une structure, demander des données et les modifier. Une base de données regroupe les données ; un SGBD, système de gestion de base de données, est le logiciel qui les gère. En anglais, on parle de DBMS, Database Management System.

SQLite est un moteur embarqué : une bibliothèque est intégrée à l’application et la base est habituellement un fichier. PostgreSQL, MySQL et SQL Server sont souvent utilisés comme services distincts auxquels une application se connecte. Une table représente un ensemble de lignes de même structure ; chaque colonne porte un champ, par exemple le nom d’un contact.

Dans notre salle, tous les niveaux utilisent SQLite. sql.js fait fonctionner le moteur dans le navigateur. Le terminal ne se connecte pas automatiquement à PostgreSQL ou MySQL. La base et les brouillons sont conservés dans ce navigateur ; l’export permet de reprendre les données ailleurs.

SQL est déclaratif : tu demandes un résultat ; le moteur analyse, planifie puis exécute la requête. Il ne faut pas classer SQL exactement comme un programme C compilé ou un script Python interprété. Des dialectes existent : tous les moteurs ne possèdent pas les mêmes types, fonctions et commandes.

2. Un seul exemple pour comprendre le CRUD

CRUD développe Create, Read, Update, Delete : créer, lire, modifier et supprimer une donnée. Nous gérons un répertoire de contacts. id identifie chaque personne ; deux personnes peuvent porter le même nom sans être la même ligne. Les requêtes ci-dessous sont un exercice autonome SQLite, à essayer sur une base d’exercice distincte si la table contacts existe déjà.

Préparer la structure

CREATE TABLE contacts (
    id INTEGER PRIMARY KEY,
    nom TEXT NOT NULL,
    email TEXT UNIQUE
);

INTEGER PRIMARY KEY déclare une clé primaire entière. NOT NULL exige un nom. UNIQUE interdit les doublons d’e-mail non nuls selon les règles du moteur. CREATE TABLE prépare la table ; il n’ajoute pas encore une personne.

C — Ajouter une ligne

INSERT INTO contacts (nom, email)
VALUES ('Tiana', 'tiana@example.com');

Les valeurs correspondent aux colonnes dans le même ordre. En SQLite, l’identifiant entier peut être généré quand on l’omet dans ce cas. Les apostrophes entourent le texte ; doubler une apostrophe permet de l’écrire dans un littéral SQL. Dans une application, utilise des requêtes paramétrées plutôt que concaténer directement une saisie.

R — Lire

SELECT id, nom, email
FROM contacts
ORDER BY nom, id;

SELECT choisit les colonnes, FROM la table et ORDER BY le tri. Cette requête ne modifie pas les données. Lis l’identifiant réel de la ligne pour les étapes suivantes.

U — Modifier une ligne choisie

-- Remplace 1 par l’identifiant réellement obtenu.
SELECT id, nom, email FROM contacts WHERE id = 1;
UPDATE contacts SET nom = 'Tiana Rakoto' WHERE id = 1;
SELECT id, nom, email FROM contacts WHERE id = 1;

WHERE limite les lignes concernées. Le premier SELECT permet de vérifier la cible, le second le résultat. Sans filtre, UPDATE peut modifier toutes les lignes.

D — Supprimer la ligne choisie

DELETE FROM contacts WHERE id = 1;
SELECT id, nom, email FROM contacts;

Supprimer une ligne et supprimer une table sont différents : DELETE retire les données concernées ; DROP TABLE retire la structure. Une action qui change les données ne renvoie pas obligatoirement un tableau de résultats.

Une transaction regroupe des opérations qui doivent rester cohérentes : BEGIN commence, COMMIT valide et ROLLBACK annule les modifications non validées. Dans le terminal DevAfrica, essaie ces commandes dans un même lot. L’atelier ajoute sa propre protection de copie de base pour conserver le dernier état réussi si le lot échoue ; ce comportement de l’atelier n’est pas à supposer dans tous les clients SQL.

4. Où intervient l’ORM ?

ORM signifie Object-Relational Mapping, correspondance objet-relationnel. Il relie des objets du langage à des tables et traduit les opérations en SQL. Un modèle décrit généralement une table ; un objet enregistré représente une ligne. Une migration décrit une évolution du schéma. Ces trois éléments n’ont pas le même rôle.

Par exemple, un modèle Django Task possède un titre et un état. Task.objects.create(title='Apprendre') crée une tâche ; Task.objects.filter(done=False) lit les tâches restantes ; une modification suivie de save() met à jour ; delete() retire la ligne concernée. Les noms exacts de table et de colonnes viennent de la configuration du modèle.

Eloquent propose ce rôle dans Laravel ; JPA définit des interfaces de persistance Java et une implémentation comme Hibernate réalise le mapping. Mongoose cible des documents MongoDB : c’est un ODM, Object Document Mapping, pas un ORM relationnel.

Changer le SGBD dans la configuration d’un ORM ne garantit pas une portabilité parfaite. Il reste à vérifier les champs, contraintes, fonctions, requêtes spécifiques et performances. Les permissions de l’application et les droits du compte de base sont aussi deux niveaux distincts.

5. Reprendre un exercice avec un autre système

  1. Choisis une version et son pilote. Consulte la documentation du framework et celle du SGBD, puis prépare une base d’exercice distincte.
  2. Recrée la structure. Adapte les identifiants générés, les types, les valeurs par défaut, les contraintes et les relations. Une base .sqlite exportée ne s’ouvre pas directement comme une base PostgreSQL.
  3. Transfère les données. Un CSV contient des valeurs, pas tout le schéma, les index et les permissions. Vérifie les accents, séparateurs, valeurs absentes et dates.
  4. Adapte les requêtes. Vérifie pagination, fonctions de dates, concaténation, comparaisons et commandes d’inspection. PRAGMA est propre à SQLite.
  5. Teste les quatre opérations CRUD. Utilise les mêmes exemples et résultats attendus ; vérifie les doublons, relations et limites pertinentes.
  6. Observe le plan et les transactions. Les performances et la concurrence peuvent changer même quand le résultat paraît identique.
